# Project Goal

Implement a bit-accurate hardware realization of a MIMO equalizer chain.

Current processing flow:

```text
Received Vector y
        │
        ▼
Hermitian Generator
        │
        ▼
Matched Filter
        │
        ▼
z = Hᴴy
        │
        ▼
Equalizer (future stage)
        │
        ▼
Estimated Symbols
```

The final objective is numerical equivalence between:

```text
MATLAB fixed-point model
```

and

```text
RTL simulation
```

including:

* fixed-point scaling
* rounding
* overflow behavior
* pipeline timing
* valid propagation
* matrix indexing
* complex arithmetic

The design prioritizes MATLAB equivalence over area optimization.

# Important Design Assumptions

The following assumptions are currently baked into the architecture and should be reviewed before changing anything.

---

## Assumption 1

Matched filter coefficient loading is registered.

Timing model:

```text
hh_load[N]
must occur

1 cycle before

valid_in[N]
```

because coefficients are stored before use.

Any modification to coefficient generation or Hermitian integration must preserve this timing relationship.

---

## Assumption 2

MATLAB behavior is the golden reference.

Whenever there is a conflict between:

```text
RTL simplification
```

and

```text
MATLAB equivalence
```

MATLAB equivalence wins.

---

## Assumption 3

Overflow behavior is wrap-around.

No saturation is used.

---

## Assumption 4

Convergent rounding is required wherever MATLAB uses:

```matlab
fimath(
    'RoundingMethod','Convergent'
)
```

# Current Open Question

The matched filter currently stores:

```text
hh_real
hh_imag
```

internally.

However a new Hermitian module now exists.

The key architectural question is:

Should the design remain:

```text
H
 ↓
Hermitian Generator
 ↓
Stored Hᴴ
 ↓
Matched Filter
```

or be refactored into:

```text
H
 ↓
Direct conjugate-transpose access
inside matched filter
 ↓
Matched Filter
```

where:

```text
coef_real[row][k]
    = H_real[k][row]

coef_imag[row][k]
    = -H_imag[k][row]
```

is generated directly without storing Hᴴ.

This tradeoff should be analyzed carefully before implementation.

# Recommendations and Suggestions

When reviewing the design, pay particular attention to:

### Architecture

* Whether storing Hᴴ is actually necessary.
* Whether Hermitian generation can be fused into the matched-filter coefficient path.
* Whether coefficient storage can be reduced.

### Verification

* Look for missing corner cases.
* Look for rounding edge cases.
* Look for overflow edge cases.
* Look for parameterization failures.

### Fixed-Point Arithmetic

* Confirm every scaling step.
* Confirm every word-length transition.
* Confirm all wrap behavior.
* Confirm convergent rounding correctness.

### Timing

* Validate coefficient-loading assumptions.
* Validate valid-signal propagation.
* Validate latency calculations.
* Validate burst behavior.

### Code Quality

* Look for synthesis portability issues.
* Look for simulator-specific constructs.
* Look for generate-loop edge cases.
* Look for hidden assumptions tied to the 8×8 configuration.

### Final Objective

The final deliverable should be a hardware equalizer chain that remains:

```text
MATLAB-equivalent
Pipeline-correct
Synthesizable
Parameterized
Verification-driven
```

with all stages validated against golden vectors before proceeding to the next stage.
